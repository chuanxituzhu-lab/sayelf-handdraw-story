本地既有视觉叙事能力存在双出口与连续性思想，但检索到的示范插件使用固定三镜头与固定场景。改进目标不是重建生图模型，而是事件驱动帧数、单一数据源、预览窗口、平台画幅和零安装的客户工作面。

## 可测差异与边界
客户运行依赖0，默认自动网络请求0；所有图片条目和视频条目从 frames 派生；添加、拆分、合并、删除后数量与编号同步。单文件 HTML 负责本地结构整理与预览，StoryAI 仅在用户点击生成时调用指定 endpoint 或宿主 AI Harness。没有把离线规则包装成语言模型，也不托管 API key。

Core只负责故事规划与验证；style是可替换数据；草图表现函数与出口函数独立。替换规划器只需返回相同项目结构。没有为了“可扩展”建立插件市场或服务层。

## 八项原则落地
1. 负熵：唯一对象是故事及其镜头，默认输入→执行→结果。
2. 模块化：规划、验证、样式、草图、出口边界分离，单文件封装不等于逻辑耦合。
3. 本地优先：拆镜、检查、绘图、下载全部在设备端完成。
4. 状态驱动：输入变化废止旧结果，用户执行才重算；无轮询。
5. 有界自动化：原文依据是观察，拆镜是推断，创意补写是草案；格式检查不代表事实审查。
6. 证据演进：先测试再交付、独立版本包、JSON可保存；无自动更新，保留旧包回滚。
7. 人机界面：单一输入入口、可见风格、可修改结果；深层出口收在“更多出口”。
8. 数据主权：无遥测、云存储、API key或自动外传；AI交接只准备本地文件，由客户自行确认可发送范围。

## 数据与发布
本产品只生成本地交付文件；默认不上传文章或媒体。未知和敏感输入留在本地；原会话截图和个人路径不进入交付包。新代码、文案和 SVG 图形为本次创作，未嵌入第三方库或素材。AI 生成时仅发送用户当前选择的镜头提示词，API key 不进入 JSON、ZIP 或 GitHub。

## 认识边界
离线拆镜按标点与段落进行，并非语义理解；较长输入按相邻片段组合，原文依据保留。简单几何草图不能精准表现任意故事，最终画面以制作清单和生图结果为准。宿主AI质量、实际生图连续性与视频成片不在离线测试结论中。
